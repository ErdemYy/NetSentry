# NetSentry AI — Machine Learning Methodology

## 1. Scientific Principles & Integrity
- **Zero Synthetic Hallucination:** Under no circumstance are model metrics manually fabricated or hardcoded into documentation or UI. Every reported metric must stem from verifiable evaluation artifacts generated on testing splits.
- **Strict Data Leakage Prevention:**
  - Feature scaling parameters (e.g. `StandardScaler` mean and variance) are computed strictly on the training set and applied idempotently to validation/test sets.
  - Flow identifier attributes (e.g., `Flow ID`, exact IP addresses, packet timestamps) are excluded from model training to prevent the model from memorizing specific network topologies rather than general traffic behaviors.
- **Reproducibility:** All random splits, tree estimators, and sampling operations utilize fixed seeds (`random_state=42`).

## 2. Dataset Strategy (CIC-IDS2017)
The primary benchmark dataset is **CIC-IDS2017**, generated by the Canadian Institute for Cybersecurity:
- **Characteristics:** Contains real-world PCAP captures spanning 5 days (Monday to Friday) covering benign background traffic alongside multi-vector attacks.
- **Attack Classes:**
  1. *Benign* (Baseline background traffic)
  2. *DoS / DDoS* (GoldenEye, Hulk, Slowhttptest, Slowloris, LOIC)
  3. *Port Scan* (Nmap reconnaissance)
  4. *Brute Force* (FTP-Patator, SSH-Patator)
  5. *Web Attacks* (SQL Injection, XSS, Brute Force)
  6. *Botnet* (ARES botnet traffic)
  7. *Infiltration* (Dropbox exploit and lateral scan)

## 3. Supervised Model (LightGBM / XGBoost Baseline)
- **Objective:** Multi-class classification of known malicious flow signatures.
- **Loss Function:** Multi-class log loss (`multi:softprob` or `multiclass`).
- **Feature Selection:** Correlation filtering, Mutual Information ranking, and Tree feature importance.
- **Cross-Validation:** Stratified 5-Fold Cross Validation.

## 4. Unsupervised Anomaly Detection (Isolation Forest)
- **Objective:** Detect deviations from expected benign network traffic distributions without requiring labeled attack samples.
- **Training Strategy:** Trained exclusively on pure benign flows from the Monday capture session.
- **Anomaly Score Formulation:**
  $$s(x, n) = 2^{-\frac{E(h(x))}{c(n)}}$$
- **Threshold Selection Methodology:**
  The anomaly threshold $\tau$ is determined by calculating the empirical 95th/99th percentile of anomaly scores on an independent benign validation set, rather than an arbitrary heuristic.

## 5. Hybrid Threat Synthesis
The detection engine computes both signals simultaneously:
```
IF supervised_class == 'BENIGN' AND anomaly_score < tau:
    verdict = 'NORMAL'
ELIF supervised_class != 'BENIGN' AND supervised_confidence >= 0.85:
    verdict = 'KNOWN_ATTACK'
ELIF supervised_class == 'BENIGN' AND anomaly_score >= tau:
    verdict = 'UNKNOWN_ANOMALOUS' # Outlier requiring analyst inspection
ELSE:
    verdict = 'HIGH_RISK'
```

## 6. Explainable AI (XAI) via SHAP
- **Implementation:** `shap.TreeExplainer` applied to the top predicted class.
- **Output:** Top-5 contributing features and their Shapley values $\phi_i$.
- **Analyst Explanation:** Converted to dynamic human-readable rationales:
  *"Classification as DDoS driven primarily by `flow_packets_per_sec` (+0.42 contribution) and `bwd_packet_length_mean` (+0.31 contribution)."*
